# YourBuddy Desktop

English | [中文](README.zh.md)

This Tauri application embeds the existing `dsh web` client and adds the YourBuddy product assembly, including Pomodoro. The default Bootstrap DMG carries the signed shell, fixed pnpm package, component manifest, and desktop overlay. Immutable Harness, Node, pnpm Store, and Harbor archives are published beside it; the separately labeled Offline DMG seeds those same archives without creating a second runtime layout.

## Runtime layout

| Resource | Runtime behavior |
|---|---|
| `component-channel` | Signed release manifest and fixed pnpm 11.7.0 package embedded in both installers |
| `component-seeds` | Offline-DMG-only copies of the exact release archives imported into the shared component cache |
| `YourBuddy/components` | Signed, content-addressed Harness, Store, Node, and on-demand Harbor components with staging and active state |
| `desktop-overlay` | Selects the Codex Agent Preset and registers notifications, the Codex subagent provider, Codex Auth/Search/Image, Better Sidebar, Ego Browser, Context Doctor, Plugin Marketplace, Personal Workbench, Oil Creator, and Harbor Evolution through `dsh web --patch`; the Web bundle mounts Pomodoro |
| `YourBuddy/dsh-home` | Isolated sessions, settings, credentials, and web profile |
| `YourBuddy/workspace` | Fallback Harbor Workbench root when no standard profile instance is active |

The product sources live in `product/harbor-evolution`, `product/harbor-python`, `product/dsh-codex-auth`, `product/dsh-better-sidebar`, `product/ego-browser`, `product/context-doctor`, `product/plugin-marketplace`, `product/pomodoro`, `product/personal-workbench`, and `product/oil-creator`. `scripts/bundle-harness-source.mjs` places the nine product Cordis packages and Harbor Skill in the trimmed workspace and adds them plus the in-tree `@deepseek-ai/dsh-subagent-codex` package to the CLI dependency closure, so the Host resolves every default plugin without a registry install. The generated bundle manifest records the Codex subagent package version and the product's Agent Presets separately from the externally refreshed product snapshots. Codex Auth, Better Sidebar, Plugin Marketplace, and Pomodoro are pinned to reviewed npm tarballs. Harbor's JavaScript and Python snapshots come from one reviewed GitHub Release. Ego Browser, Context Doctor, and Oil Creator are pinned to reviewed GitHub branch commits; Oil Creator's declared package-manager build runs before the npm package file selection is frozen. Each externally refreshed snapshot records its immutable source, integrity hash, committed tree hash, upstream license, exact-version peer-metadata overrides, and reviewed functional compatibility patches in `YOURBUDDY_UPSTREAM.json`. `scripts/prepare-yourbuddy-runtime.mjs` installs the committed Python snapshot into a relocatable resource and accepts `YOURBUDDY_HARBOR_PYTHON_SOURCE` for temporary local adapter testing.

## Default-plugin delivery policy

Default external plugins are reviewed snapshots in the frozen workspace rather than packages fetched by `dsh plugin add` during application startup. A runtime Git installation would target the wrong home if it used the user's `~/.dsh`, make cold boot depend on GitHub and local build execution, and let a mutable branch change the application without a YourBuddy release. The in-box dependency closure preserves offline startup and binds source, compatibility metadata, and transitive resolution to the release. Refresh compatibility compares bundled release-candidate packages with peer ranges using SemVer prerelease ordering; exact-version metadata corrections remain explicit in the product update policy.

This policy increases the installer by each plugin's packed files and shared Store entries and couples upstream updates to a YourBuddy release. Ego Browser contributes approximately 314 KB packed and 1.2 MB unpacked, including its integrity-pinned SDK runtime but excluding Chromium and optional FFmpeg downloads. On macOS, the reviewed compatibility patch discovers standard native browser installations and bypasses the Linux X11/Xvfb path. Each Ego Browser or Harness update therefore requires refreshed source records, lockfile regeneration, compatibility validation, and the assembled Client smoke. An active user-installed Profile bundle takes precedence over the uniquely named in-box fallback, so independent updates remain possible but return version and compatibility ownership to the user.

The bundle generator derives a system Agent Preset with id `codex` and display name **Codex** from the shipped Standard composition, enabling its existing `subagent_codex` row while leaving the other shipped presets unchanged. The desktop overlay selects Codex as the base default, so a fresh Profile and any new Session with no explicit selection can delegate immediately; a user's explicit default remains authoritative, and existing Sessions retain the composition recorded when they started. The overlay also reserves the external `codexhost-delegation` skill from autonomous model routing, so generic Codex delegation uses the preset's native, tracked `subagent_codex` tool even when that user-level skill is installed; a user can still request the external path explicitly with `/codexhost-delegation`. Loading the provider starts no Codex process. A native delegation starts the package-local official Codex runtime in the Session workspace and uses native Codex configuration and login state rather than credentials copied into YourBuddy settings.

The generator also derives the **内容创作** Agent Preset from Codex. It keeps the complete Standard toolset and native Codex delegation, then replaces the coding persona with a creator-workbench persona. Oil Creator remains a Host plugin because one package owns its sidebar, settings, Remote, model tools, Skills, and system-prompt section; the preset specializes the Agent without mounting a duplicate service. The plugin bundles video publishing, video-to-article, and WeChat Official Account draft Skills and exposes one draft-preparation tool while leaving final publication to the user. Its Sidebar keeps the Personal Workbench name, Logo, and desktop window controls. Codex remains the default preset.

The desktop overlay makes `danger-full-access` (**Full access**) the base permission preset for new Sessions. This preset does not confine file access or request approval for tool calls. An explicit default saved in General settings remains authoritative, and the product base never rewrites an existing Session.

Every Agent-facing Harbor Tool resolves its root from the calling session's absolute working directory. Selecting `/Users/me/project` in a YourBuddy session therefore keeps initialization and later Agent-created Harbor artifacts inside that project. The desktop overlay's configured application-data `projectRoot` remains only the global Web Workbench and non-Agent fallback; Agent Tools neither use it nor reject a session because it differs.

Harbor resolves and freezes the Candidate model through the Host `agentDefaultModel` and LLM services before it starts a Job. A loopback-only Host broker then exposes that exact route to the Docker task through a random Job-scoped URL and bearer capability. The Python adapter performs an in-container health check before installing or starting the Candidate, generates an ephemeral Cordis overlay under `.harbor-runtime`, and replaces only the Candidate ACP model route with `yourbuddy-host/<frozen-model>`. The original Candidate remains immutable, and the Codex OAuth credential never enters its files, configuration, or container environment. The model binding is part of Evaluation Context v2, so a different provider, model, reasoning effort, transport, or protocol cannot reuse an old comparison baseline.

Host Node reuse requires both the supported version and the native CPU architecture. Global pnpm installations are never adopted; YourBuddy installs its embedded fixed pnpm package. Bootstrap first performs the frozen production install against pnpm's normal per-user Store. Only a content miss activates the signed Store component and repeats the same offline install with an explicit Store path; an incompatible or absent Host Node similarly activates the signed Node component. Harbor remains discoverable without Python. A `HARBOR_RUNTIME_NOT_READY` error offers the signed Harbor component installation in place, reports installation failures separately, and reloads Harbor after success.

The application prepends its private `dsh`, Node, pnpm, and Capability Pack shims to the Host process tree. **Enable terminal commands** adds the stable private bin directory to the user's shell profile without a global npm installation. An explicitly declared Capability Pack exposes only its package-owned entries, Skills, Host/UI bundle, and version through one installed package; reconciliation updates its owned shims atomically, reports external command conflicts, retains the old installed package after a failed plugin update, and removes only unchanged owned shims on uninstall. The repository workspace and isolated Web Profile set `dangerouslyAllowAllBuilds: true`, so dependency lifecycle scripts run without a separate pnpm approval; generic DSH Profiles retain their own build policies. Product plugin overlays reuse an active standard Profile Bundle by package name and enable a uniquely named in-box fallback only when no prior mount exists, so a user-installed bundle does not create a duplicate Loader ID. During an upgrade, the native boot path repairs this Web Profile policy, rebinds only YourBuddy-managed `link:` dependencies that still point into this application's older content-addressed Harness trees, and runs the standard Profile install when either operation changes managed state; registry dependencies and links outside the YourBuddy application-data tree remain user-owned and unchanged.

Plugin Marketplace uses the public GitHub `dsh-plugin` topic only for discovery. Opening a result searches npm and enables one-click confirmation only when a package declares `dsh.bundle.patch` and its metadata links it to that repository through the Repository field or owner-scoped DSH upstream metadata; this selects a DSH Bundle from repositories that publish SDK, CLI, and other npm packages and resolves scoped packages whose npm name differs from the repository basename. Missing, ambiguous, or incomplete metadata keeps confirmation disabled. A confirmed install runs `dsh plugin add` against the isolated Web Profile, keeps its progress or actionable pnpm failure associated with that package, and grants installed code the same Host privileges as a manual DSH plugin install. Repository and npm links use a fixed iframe message protocol whose shell and Rust validators allow only an HTTPS GitHub repository, npm search, or npm package page before the system browser opens it.

The desktop shell launches its private Host with `dsh web --no-open` and treats the process-token URL printed after Loader settlement as the readiness signal. Native code completes the exchange without following the redirect, installs the returned cookie, and discards the token URL before creating the main WebView. The privileged shell is served from an application-owned random `127.0.0.1` port with a runtime capability restricted to that exact origin and the `main` window. Tauri grants local product documents and this runtime-owned shell one stable first-party command gateway; application code dispatches its operations directly instead of maintaining a product command ACL, so a newly added operation cannot be blocked by a stale capability list. Operating-system permission prompts, code signing, and explicit plugin installation or activation remain authoritative. The Host iframe receives no direct Tauri capability. Its different origin remains on the same HTTP site, so the original `HttpOnly; SameSite=Strict` cookie remains effective on macOS WebKit. The startup URL never enters the renderer, `boot.log`, a user-facing failure, or the operating system's default browser. The frameless main window projects platform window controls into the expanded sidebar header immediately before its collapse button; macOS uses a horizontal red/yellow/green group with no divider. A small floating Shell fallback keeps the actions available during startup, reload, and the collapsed-sidebar state without reserving a full row or column. The system tray remains available for showing or quitting the application. See the [desktop same-site authentication note](../../.agents/notes/implemented/bug-fix/2026-09-06-yourbuddy-desktop-same-site-authentication.md).

Assistant Markdown continues to use the shared renderer's HTTP(S) allowlist. In the desktop product, the Personal Workbench Client intercepts only its external `_blank` anchors and asks the parent shell to open them in the operating system's default browser. Hover exposes the destination, and the link context menu can open or copy it. The shell accepts the fixed versioned request only from the active Host iframe at its exact origin; both the shell and Rust command require a bounded, credential-free HTTP(S) URL. Relative links, same-origin routes, downloads, file mentions, and schemes such as `javascript:`, `file:`, and `data:` never enter the native opener.

Release builds read the semantic application version embedded by Tauri and run one signed update check at a time after the main window opens. The stable `yourbuddy-updater` manifest must advertise a higher version before YourBuddy downloads anything; the check has a 15-second deadline, while a failure leaves the running workbench unchanged. The tray shows the current version and supports a manual check. **Settings → General → Application lifecycle** exposes **Check and update**, **Install Harbor runtime**, **Enable terminal commands**, and **Restart YourBuddy**. The loopback Client sends fixed versioned lifecycle requests from the active workbench iframe; the shell maps them to the stable first-party gateway. An update announces the current and target versions before Tauri verifies and installs the signed artifact. A manual restart and a successful update both stop the private Host before relaunching the application. These user actions never run local release preparation or download plugin source: bundled product plugins advance only as part of the signed YourBuddy release.

**Settings → General → Network proxy** owns one application-wide policy rather than a Codex-specific transport toggle. Direct mode removes ambient proxy variables; system mode reads fixed macOS HTTP and HTTPS endpoints with `/usr/sbin/scutil`; custom mode requires separate credential-free HTTP and HTTPS URLs and accepts additional bypass hosts. PAC, automatic proxy discovery, and HTTP-only macOS configurations fail with an actionable message because they cannot be translated faithfully to the complete Node process tree. Native reqwest clients and the signed updater use rustls with the platform verifier, while every application-owned Node process receives `--use-system-ca`. A user can also select one PEM-encoded `.pem` or `.crt` enterprise CA bundle through the native file picker; YourBuddy validates and canonicalizes the file, stores its path, adds its roots to native platform trust, and sets `NODE_EXTRA_CA_CERTS` before spawning the Node Host and plugin processes. The explicit bundle supplements system trust and never disables certificate validation. The test checks the desktop draft route and the running Node Host global `fetch` separately and labels their HTTP or bounded certificate and transport results, proxy mode, and CA source independently, so one successful route cannot mask the other's failure; when the draft differs from the active Host policy, the result asks for a save, restart, and second test. Saving invokes only the fixed network-settings command and then the fixed application restart command; the restart terminates and waits for the private Host before relaunch, after which the Host, plugins, package installation, runtime provisioning, and signed updater all use the same resolved policy. Loopback addresses always bypass the proxy, and running processes keep their previously activated policy until restart.

The Tauri-owned splash and loopback shell do not set browser resource policies such as Content Security Policy, Cross-Origin Resource Policy, referrer policy, or MIME sniffing restrictions. The Host overlay policy permits loopback HTTP media and HTTP(S) connections so installed workbench plugins can use their local HTTP services. The shell server still accepts only its exact loopback `Host`, serves its three embedded assets without caching, and stops with the application.

## Local release preparation

Run the networked product refresh explicitly before reviewing and committing a release input:

```sh
pnpm --dir apps/desktop-tauri run prepare:release
```

The DSH policy selects the highest official stable Release and falls back to the highest RC only while no stable Release exists; alpha, beta, other prereleases, and `master` are excluded. When the selected tag is newer, release preparation requires a clean worktree, fetches and verifies that exact tag commit, leaves its upstream merge uncommitted for review, records it in `product/DSH_UPSTREAM.json`, and retargets the approved product peer metadata before compatibility checks. The remaining refresh policy queries npm's latest stable versions for Codex Auth, Better Sidebar, Plugin Marketplace, and Pomodoro, the latest stable Harbor GitHub Release for the paired Cordis plugin and Python adapter, and the Context Doctor `main` head. Personal Workbench is first-party and receives only the selected DSH peer version. GitHub API reads prefer `GITHUB_TOKEN` or `GH_TOKEN`, then reuse an existing `gh auth` login when available; the credential is never written to source record. The command does not search backward for an older compatible release: an incompatible selected candidate fails so its policy or code can be reviewed. A peer-metadata override is accepted only when `product/plugin-update-policy.json` names the exact upstream version; a functional compatibility patch remains explicit in source record and must continue to pass the assembled release smoke.

The policy is validated before any managed path is copied or removed: destinations must remain under `product/`, source paths must remain under the downloaded checkout, and managed paths must be unique and non-overlapping. All archives use HTTPS, compressed and expanded byte limits, entry-count limits, and safe extraction; npm artifacts must match the registry SRI, and every archive receives digest-bound source record. Candidates remain in staging until the complete set passes package identity, managed Node, DSH peer, bundle patch, Host entry, Client entry and injection, license, and tree checks. The command then replaces the managed snapshots as one operation, rebuilds Harness with the same explicit Client environment as tagged CI, regenerates `product/harness-pnpm-lock.yaml`, and proves every product DSH/Cordis peer in both the lockfile and installed tree points to the bundled workspace instead of a second runtime. It prepares the digest-bound offline Store and performs the real `--prod --frozen-lockfile --offline` install. Release acceptance and native first launch disable pnpm's automatic version switch and trust the committed lockfile because the product independently pins the pnpm archive and verifies the Store and bundle digests. The Harbor commands and assembled Host run with a credential-scrubbed environment plus temporary home, DSH, and temporary directories. Headless Chromium must receive all nine product Client bundles, activate every Client Loader entry without page or console errors, mount the workbench, show Codex as the default Agent Preset, expose the Plugin Marketplace navigation entry, exercise a safe assistant-link DOM contract through hover, right-click copy, and the system-browser command, exercise the Network proxy draft test and save-and-restart controls, expose the Application lifecycle update and restart controls, reject one-click installation when the repository has only a non-DSH npm package, select a differently named scoped DSH Bundle while ignoring a sibling SDK package, invoke only the restricted general and Marketplace external-link, network-settings, signed-update, and application-restart commands, enable installation confirmation, and render a package-specific persisted failure; the same smoke requests the Context Doctor API and requires the Host to shut down normally. A failure at any later stage restores every managed snapshot and the product lockfile.

Managed product paths must be clean by default. `pnpm --dir apps/desktop-tauri run prepare:release -- --allow-dirty` is an explicit escape when the developer has already reviewed the local product edits that the transaction will preserve or replace; it never permits an upstream DSH merge in a dirty worktree. A successful run leaves the DSH merge, refreshed snapshots, and lockfile for human review and commit; `DSH_UPSTREAM.json` records the official DSH tag and commit, each `YOURBUDDY_UPSTREAM.json` records the exact external revision plus archive and tree hashes, and the generated `.bundle-manifest.json` records these inputs plus the whole-bundle hash. Any later preparation failure aborts an owned DSH merge and restores the managed product inputs.

To refresh one external product source without advancing unrelated snapshots, pass its policy id, for example `pnpm --dir apps/desktop-tauri run refresh:product-plugins -- --only=harbor-evolution`.

Tagged CI and ordinary `prepare:dist` or `build` commands never mutate or re-resolve upstream inputs. The tag workflow consumes only that tag's committed snapshots and frozen lockfile. Manual workflow dispatch may retry an existing unpublished tag after a failed run. The workflow refuses any tag that already has a GitHub Release, so correcting published bytes requires a new version instead of replacing an installer.

On a clean `master`, `pnpm release:yourbuddy:prepare -- X.Y.Z` updates every desktop version source, creates the bilingual release archive and index entries, records their pairing files, and writes a release-notes draft without network access. Replace every generated `TODO`, re-record the changed pair, review, and commit. `pnpm release:yourbuddy -- X.Y.Z` then validates only the committed version archive and Git state; it does not repeat tests, product refresh, documentation checks, or the website build. It requires `master` to fast-forward `origin/master`, rejects an existing remote tag, creates or reuses only a same-commit annotated tag, and atomically pushes the branch and tag. The tag workflow remains the only publisher of desktop artifacts.

## Commands

Run from the repository root:

```sh
pnpm install --frozen-lockfile
DSH_CLIENT_TITLE=YourBuddy pnpm run build
pnpm --dir apps/desktop-tauri run test:bundle
pnpm --dir apps/desktop-tauri run test:offline
pnpm --dir apps/desktop-tauri run test:overlay
pnpm --dir apps/desktop-tauri run test:update-manifest
pnpm --dir apps/desktop-tauri run test:release-version
pnpm --dir apps/desktop-tauri run sync:dsh -- --dry-run
pnpm --dir apps/desktop-tauri run prepare:release
pnpm --dir apps/desktop-tauri run prepare:product-runtime
pnpm --dir apps/desktop-tauri run build
pnpm release:yourbuddy:prepare -- X.Y.Z
pnpm release:yourbuddy -- X.Y.Z
```

The current target is `aarch64-apple-darwin`; the release workflow intentionally has no Windows, Intel macOS, or Linux matrix rows.

The macOS arm64 release workflow verifies the tag against every desktop version source, builds and signs one component manifest, produces Bootstrap and Offline DMGs from the same component set, and publishes the component archives with their size report. The Bootstrap DMG is rejected above 30,000,000 bytes or when it contains a Harness tree, Node archive, pnpm Store, Harbor runtime, or Offline seeds. `latest.json` points to the signed Offline application archive so an automatic update installs every release seed before restart. The workflow relocates the published Harbor component and runs both entry points before checksumming and publishing every asset.
