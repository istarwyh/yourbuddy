# dsh-yourbuddy-design

English | [中文](README.zh.md)

YourBuddy bundles `dsh-claude-design` and `dsh-claude-artifacts` at 2.11.1 through exact dependencies and the frozen Harness lockfile. The offline Store contains the published payloads; the repository keeps only integration patches and [source records](UPSTREAM.json). The packages retain their own LICENSE, NOTICE.md and editor third-party notices. Their mixed terms are not collectively MIT, and the source record does not resolve the upstream notice's unlicensed Anthropic-origin material.

## Use

The Artifacts sidebar starts a fresh, unsent `/claude-design` draft in the current workspace. It preserves the selected Agent Preset and uses YourBuddy's configured default model. Existing drafts are untouched. The model writes `project/canvas.json` and `.dc.html` files under the Session workspace, then calls `yourbuddy_design_open`; choose the artifact in Artifacts to open the editor in the application. Ordinary chat links still open the system browser. Creation controls stay disabled until the Workspace and Session lists arrive, with localized loading text or a Workspace/Session-list failure message. Becoming ready does not replay earlier clicks.

The managed Host Node starts one foreground editor child per canonical artifact folder. Repeated opens reuse that child. Another Session cannot adopt its live editor, and a server started outside YourBuddy is left untouched. Disable the adapter or exit the Host to stop its children; plugin-load failures remain separate from the workbench. The Plugins page controls the three product rows. Upgrades come with the application rather than upstream's independent updater.

Send to Agent queues a notice with the upstream comment card into the associated Session. A stable Session/folder/thread/send identity deduplicates retries, and the editor marks delivery only after the Session writer flushes. Explicitly canceled receipts stay canceled. Unacknowledged comments remain in comments.json and retry when the editor restarts. Agent replies use upstream comment-reply on the same folder. Non-comment page-button agent requests are not supported: the endpoint rejects them with HTTP 409 before accepting them; use a saved comment and Send to Agent instead.

## Configuration and verification

The adapter accepts startupTimeoutMs (20000) and stopTimeoutMs (5000). It binds only 127.0.0.1 on an assigned port, uses no shell to start the editor, and strips credential-named environment variables. Managed editors ignore persisted LAN-sharing settings and reject enabling LAN Share; existing sharing files are not rewritten. The editor's iframe and local file-export paths keep upstream behavior and existing desktop permissions.

After building and installing the bundled Harness with its frozen lockfile, run `pnpm --dir apps/desktop-tauri run test:design`. This runs the Node regressions against the installed pair, the dedicated production AgentLoop/JSONL and real Cordis Client-injection tests, and the real Web profile through Loader, tool execution, Artifacts routes, Delete/Undo/reopen, and Chromium Client boot. Set `YOURBUDDY_RELEASE_CHROMIUM_EXECUTABLE` when Chromium is installed outside Playwright's cache. `--host-only` explicitly omits browser execution. The Web smoke enables the Browser tab as the native desktop overlay does and captures managed-open errors before their toast disappears. The Host fixture registers its temporary Workspace before creating its Session; first-use initialization is not a fallback for an installation with existing Sessions but no registered Workspace.

Linux verification passed 22 adapter Node tests, 9 CI/evidence tests, 25 Vitest tests and the real Host lifecycle smoke. Deliberately invalid design configuration leaves the Web document and actual Session creation available. The normal offline-store preparation produced a Linux seed archive, and a clean installation restored from that archive passed with the exact frozen offline first-launch arguments. This is Linux evidence, not macOS distribution or native first-launch acceptance. Native lock contention is covered on Linux; the Windows named-pipe branch has not been run on Windows.

The Session resolver in receipt tests is a test replacement. The Bootstrap regression workflow reuses its existing YourBuddy build to prepare a real Linux offline seed, reinstall from its archive, and run Chromium acceptance, including the Artifacts entry, an unsent draft, managed iframe open, and workbench boot after feature startup failure. It requires no model credentials or publication permissions and retains the test log and, on browser failure, bounded page/error/request diagnostics and a screenshot. Network diagnostics omit URL credentials, query strings, request headers and bodies; text diagnostics use the release harness redactor. Set `YOURBUDDY_DESIGN_EVIDENCE_DIR` to retain the same evidence locally. A successful CI run is still required; wiring the job is not acceptance.

Cold Session restoration, model generation, native macOS arm64 Tauri/WebView, HTML/PDF/PNG export and desktop saving still require acceptance. The cloud runner could not launch Chromium because its Unix socket was denied, and the separate cloud browser could not reach its loopback server. These Host tests do not establish Client or native acceptance.
