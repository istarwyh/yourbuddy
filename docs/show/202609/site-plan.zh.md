# 站点结构与发布素材

[English](site-plan.md) | 中文

本页把内容底稿映射为建议网页，供 YourBuddy 官网实施时使用。以下路由是设计目标，尚未创建或部署；本次不修改现有 VitePress 导航。

## 顶层导航

建议采用“开始使用、使用指南、插件、更新日志、路线图”，右侧提供下载、语言切换和 GitHub。开发者入口放在文档导航与页脚，支持用户需要时深入。第一版聚焦一个当前版本，中英文内容同步，不建立空白 Blog 或 Book 栏目。

## 每类页面怎么写

教程按“前提 → 操作 → 成功信号 → 常见失败 → 下一步”组织。插件详情按“解决什么 → 为什么预装 → 在哪里用 → 示例 → 限制 → 来源”组织。参考页围绕一个可查询的问题展开，不把底层包目录直接变成用户导航。

首页使用 [Y8 图标](../../../apps/desktop-tauri/app-icon.svg)和当前产品文案；首页截图优先展示对话与工作产物。内部版本 Hash、Loader ID、评测 Stack 字段和测试计数放在来源或开发资料中，只有影响用户选择时才进入操作步骤。

## 需要补齐的素材

| 素材 | 要证明什么 | 拍摄／验证要求 |
|---|---|---|
| 首屏工作台截图 | 用户可以边对话边检查成果 | 同一会话展示真实文件，保留 YourBuddy 默认身份 |
| 首次使用短演示 | 安装后的基本任务可独立完成 | 记录版本、模型路径与从选择工作区到打开产物的连续步骤 |
| GPT Auth 与模型设置 | 用户有清楚的接入入口 | 隐去账号与密钥，模型可用性以实际运行结果为准 |
| Context Doctor 报告 | 诊断可定位到上下文来源 | 使用练习指令，呈现估算与重复来源，避免未经测量的节省比例 |
| 插件安装演示 | 成功与失败状态都可理解 | 展示来源、资格、确认、完成或具体错误，以及重启后入口 |
| Harbor 历史诊断 | 无数据集用户可以先观察已有任务 | 使用脱敏记录，展示确认、覆盖率和未评分原因 |
| 正式评测案例 | 一次改进有可比较的证据 | 固定任务、模型与评测身份，保留基线、回归和未验证项 |
| 下载与发布信息 | 页面对应真实可用产物 | 核对实际 Release、安装包、校验和与更新渠道 |

目前这些是素材需求，不是已拍摄、已验收的材料。上游插件截图只能标注为上游参考，不能替代 YourBuddy 集成后界面的证明。

## OINK 落地时的内容处理

建议从 [OINK Starter](https://github.com/pgsty/oink-starter) 的双语配置开始，以本页选定的栏目替换示例内容。首页写入其语言对应的 YAML 数据，产品手册使用普通 Markdown，复杂组件只在有明确阅读收益时采用。

现有仓库通过[发布映射](../../../website/docs.ts)与[投影脚本](../../../scripts/project-doc-site.ts)复用 Markdown。采用 OINK 时，应保留正文的一处维护方式，适配页面标题、导航、内部链接、锚点和少量 VitePress 语法；不能把当前工作复制成两个各自演进的完整文档库。

插件版本与下载事实取自对应发行记录，来源说明可以由固定清单生成。不要在构建时把上游 Latest 版本直接展示为本应用内置版本。站点应提供搜索、语言互跳和 Markdown 输出；中文搜索关键词可补充常见别名，如“密钥／API Key”“工作区／项目目录”“上下文／Token”。

## 发布前的内容验收

1. 每个公开能力有实际入口、适用前提与来源；草案建议留在路线页。
2. 五个默认外部插件都说明用途、入选理由、限制与作者项目，自有插件单独归属。
3. 安装、模型配置、首次任务、插件重启和历史诊断分别具有真实发行版证据或明确的未验证标记。
4. 中英文对侧页面、图片、搜索、站内链接、Markdown 输出与真实下载地址均可访问。
5. 下载页与更新日志连接对应的发布验证归档，不将构建成功写成已发布或全面支持。

该清单只描述本次官网方案的验收目标；现有仓库文档与发布要求仍分别由[文档规范](../../AGENTS.md)和[发布记录规范](../../releases/README.zh.md)负责。
