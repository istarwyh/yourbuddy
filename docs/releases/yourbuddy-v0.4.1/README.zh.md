## 面向用户的发布说明

### 改了什么

Bootstrap 组件签名现在会转换为桌面 Runtime 实际读取的格式，并在打包过程中接受密码学验证。无法激活的可选插件不再阻塞整个客户端。工作台只在右侧栏实际打开时收起，并在首个 Session 创建前继续展示不可用状态的卡片。

### 解决了什么问题

YourBuddy 0.4.0 首次启动时，组件签名可能仍使用签名工具的传输编码，导致启动停止；可选插件等待某项服务时也可能让页面停留在加载状态。右侧栏尚未打开时中间工作台可能提前消失，新工作区则看不到可用卡片。

### 在哪里使用

使用 Bootstrap DMG、可选内置或第三方插件，以及桌面工作台和右侧栏时，建议安装此版本。

### 如何体验

从 Bootstrap 安装启动 YourBuddy，创建或打开 Session，然后打开并关闭右侧栏。即使某个可选插件不可用，应用也能完成启动；右侧栏打开前工作台保持可见，打开时收起，关闭后恢复。

### 安装或升级

从 GitHub Release 安装 Apple Silicon Bootstrap 或 Offline DMG；旧版本也可以通过**设置 → 通用 → 应用生命周期 → 检查并更新**升级。现有设置、凭据、Session、工作区数据和组件缓存保持不变。

### 兼容性、迁移与限制

本版本面向 macOS Apple Silicon，不需要数据迁移。除非所需组件已有缓存，Bootstrap 首次启动需要访问匹配的 GitHub Release。应用仍未使用 Apple Developer 身份签名，也未公证。发布前验证未启动打包后的应用，也未操作打包后的 WebView 流程。

- 状态：在已说明的源码与打包输入范围内通过。

- 受测构建：候选源码、暂存的 Bootstrap 组件输入与产品快照。
- 环境：macOS Apple Silicon，本地 Node、pnpm 与 Rust 工具链。
- 证据来源：本次发布准备执行的针对性测试、原生编译、产品快照验证和仓库文档门禁。
- 数据：生成的 Manifest 与合成客户端状态；不含私有用户数据。
- 模型或服务：确定性的本地构建与测试；未调用模型。

### 操作步骤

1. 规范化代表性的 Tauri 签名输出，执行 Bootstrap DMG 大小上限，编译原生验证器，并验证已记录的产品快照。
2. 验证可选与必需客户端 Entry 的失败路径，然后围绕桌面工作台打开并关闭右侧栏。
3. 运行双语文档与 Release 引用门禁。

### 预期结果

暂存的 Manifest 与签名使用 Runtime 所需的原始 minisign 格式；原生密码学验证失败会阻止打包。可选插件失败会被报告，但不会阻塞必需应用服务。工作台收起状态跟随实际右侧栏，并在关闭后恢复；Session 尚未创建时卡片仍然可见。

### 实际结果

5 项组件测试、57 项针对性客户端测试、10 项产品 Bundle 测试、原生 `cargo check`、Better Sidebar 类型检查及全部 43 项文档门禁均通过。发布工作流现在会在打包前使用相同的原生组件验证器检查暂存通道。

### 证据

- 操作前：签名工具输出可能保留 Base64 包装；一个不可用的可选插件会阻塞客户端启动；工作台可见性跟随预期布局，而非实际右侧栏状态。
- 执行中：发布路径增加确定性的签名规范化和原生暂存通道检查；客户端激活策略和布局状态分别按职责处理。
- 结果：候选版本包含 Issue #35 要求的首次启动、可选插件和工作台交互修复。
- 失败与恢复：一次独立 Better Sidebar 构建缺少父工作区构建配置；恢复了受影响的已跟踪生成文件，将相同源码变更同步到签入的 Runtime 文件，并通过包类型检查与产品快照验证。

### 范围限制

本地未操作打包后的应用、首次启动下载、已安装 WebView 控件、Offline 无网络启动、Apple Developer 签名和公证。GitHub Actions 发布、公开文件名、Hash、更新元数据、DMG 完整性与 Bootstrap DMG 实际大小需要在发布后核验。
