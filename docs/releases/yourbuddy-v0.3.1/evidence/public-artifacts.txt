Updater archive observations
----------------------------
The updater archive extracted successfully and contained `YourBuddy.app`.
Its Info.plist values matched the DMG values above. A pristine extraction
passed `codesign --verify --deep --strict`; `codesign -dv` identified an
arm64 app with an ad-hoc hardened-runtime signature and no TeamIdentifier.
Gatekeeper `spctl --assess` rejected the app, as expected for the documented
absence of Apple Developer signing and notarization.

With `PYTHONDONTWRITEBYTECODE=1`, the updater App's packaged `harbor
--version` printed 0.21.0, `harbor-dsh --help` exited successfully, and a
second strict code-signature verification still passed.

Failures and recovery retained
------------------------------
The first stable-channel download attempt ran outside a Git checkout without
an explicit repository and failed with `fatal: not a git repository`. Retrying
with `-R istarwyh/yourbuddy` succeeded, and the manifests matched.

An initial updater extraction ran the Python entry points before checking its
ad-hoc signature. Python created bytecode cache files inside that writable
copy, so the subsequent signature check correctly reported added sealed
resources. A fresh extraction passed the signature check before execution;
running the same entry points with bytecode writes disabled preserved it.
This operator-induced writable-copy result is not presented as a defect in
the downloaded archive or as proof of an installed application lifecycle.

A direct invocation of the bundled raw `venv/bin/python` was not relocatable
without the launcher's runtime setup. The supported packaged `harbor` and
`harbor-dsh` entry points both passed, and no raw-interpreter compatibility
claim is made.

Scope limits
------------
This verification proves publication, file integrity, manifest consistency,
App identity, pristine ad-hoc signature integrity, and the two packaged Harbor
entry points. It does not prove an interactive installed-DMG UI journey,
signed in-app update installation, real GPT OAuth or model-provider traffic,
a real enterprise proxy or CA, Apple Developer signing or notarization,
automatic XiaoHui migration, macOS Intel, Windows, or Linux behavior.
