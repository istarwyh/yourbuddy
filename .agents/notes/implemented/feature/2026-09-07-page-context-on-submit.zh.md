# Agent Note: 普通提交时附带页面上下文

Status: implemented

[English](2026-09-07-page-context-on-submit.md) | 中文

## 问题

用户查看插件对象时，可以在常驻 composer 中询问“这个”，但普通提交没有携带可见对象。显式引用 chip 可以使用，但每次提问都要求引用会割裂页面与对话。在异步引用或图片准备后才捕获上下文，还可能绑定到另一页。

## 决策

现有 conversation service 拥有通用的所选 View 上下文 registry。每项贡献声明 View id、标签、准备期限和回调。input facade 在提交锁定时同步调用回调；消费方先复制页面状态，再异步解析。宿主选取当前 Session 的权威 View，而不是任意已挂载组件。斜杠命令跳过隐式上下文。

上下文是同一次 Session 提示词中的附加文本块。通用 source/label 封装将模型文本和可选的冻结 description 记录在同一条持久化用户消息中。提供方可以返回纯文本或 `{ text, label, description? }`；若有 description，Chat 与 Queue 显示该说明而非协议文本。不增加事件类型、循环注入或第二条提示词。首个文本块仍属于用户原文，包括仅图片且附带上下文时的空块；展示投影只识别后续完整封装。复制不包含自动标记；编辑队列保留原先冻结的附件。

取消、期限到期、准备失败和贡献释放会阻止接纳并保留草稿。Queue/Steer 选择、图片所有权和提交 request 身份仍属于原始尝试。消费方负责显式引用优先级、有预算且脱敏的上下文以及关闭行为。宿主不读取插件 DOM，也不理解 Harbor 身份。

每条失败消息拥有其原文、引用 chip 和图片。空 composer 可以立即恢复；若 composer 已有内容，则显示紧凑恢复条目，不修改下一份草稿。显式恢复要求 composer 为空且空闲，绝不会发送。重试捕获当前所选页面。丢弃和 Session 释放会释放失败条目的图片，各条独立失败消息绝不合并为一条。

## 考虑过的替代方案

**另一个 composer 或上下文面板。** 这会重复主输入框，使普通提问需要额外交互。相关控制和证据由现有页面及消息附件承载。

**延迟查询上下文或独立注入。** 延迟查询可能捕获更新的选择；独立注入可能进入错误的排队轮次，或与持久化用户消息不一致。一次冻结的贡献因此跟随原始接纳。

**宿主内的 Harbor 专用代码。** 其他插件 View 也需要相同的提交边界。宿主因此只暴露一个注册约定，不导入功能包或解释其对象 schema。

## 结果与代价

宿主与消费方都必须支持约定；旧宿主保留显式引用行为。持久化上下文文本可以回放，但消费方 token 仍可能过期或陈旧。宿主绝不以当前上下文替换过期证据。准备失败会阻止本次发送，直到重试或通过消费方关闭自动附带，避免看似带上下文的问题悄悄变成无上下文问题。

## 测试

包级测试覆盖同步捕获、异步引用竞争、Session 隔离、期限、卸载、取消、重试、图片所有权、已有草稿时的恢复、丢弃与释放、Queue/Steer、安全展示元数据和原文编辑。无密钥的 `conversation-page-context` 应用级浏览器测试通过 Loader 加载真实公开消费方，并比较受控模型内容与持久化用户消息内容。独立 Harbor 集成测试使用明确指定的外部插件源码；不替换内置产品，也不声称完成真实提供方评测。
