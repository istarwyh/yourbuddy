# Agent Note: 在配置发现稳定后发布 ACP 会话

Status: implemented

[English](2026-09-07-acp-session-activation-topology.md) | 中文

## 问题

ACP 会话创建与恢复会在配置发现完成前把会话写入活动会话 Map。该区间内的 `llm/adapters-updated` 事件可能在 `session/new` 或 `session/resume` 响应前发布 `config_option_update`。响应本身已经携带完整初始选项，而事件时序会使这条额外通知在不同 Host 上产生不确定结果。

## 决策

会话创建与恢复会保持 Record 私有，直到配置发现成功且会话已经可以接受客户端请求。Bridge 会统计提供方拓扑提交次数。如果初始选项发现期间该计数发生变化，就重新执行发现；创建流程还会在空会话持久化后再次检查计数。激活响应只返回稳定的选项状态。

激活完成后，提供方拓扑提交仍通过现有的逐会话更新路径发布完整配置更新。

## 验证

- ACP Bridge 测试暂停模型发现并改变提供方拓扑，证明激活响应包含新提供方，且不会提前发送会话更新。
- 独立测试暂停初始持久化，证明该区间内的拓扑变化会触发新的选项读取。
- 无密钥 ACP Transcript Corpus 固定由 `session/new` 首次承载初始配置选项，同时保留激活后拓扑更新覆盖。

## 曾考虑的替代方案

**在 Snapshot 中接受两种协议顺序。** 拒绝，因为客户端不应在发布会话的请求完成前观察到该会话的更新。

**忽略激活期间的拓扑变化。** 拒绝，因为激活完成时返回的选项状态可能已经过期。

## 后果

ACP 会话只有在激活响应就绪后才能通过 ID 访问。频繁拓扑变化可能延长配置发现；激活后的变化继续采用既有异步通知行为。
